# 데이터 라벨링 정리 (`unlabeled.csv`)

`train_unlabeled.jsonl.gz` 20,000건에 24개 위반 항목(v1~v24)의 0/1과 근거 문구(e1~e24)를 붙인 결과입니다.
**앞 400행은 사람이 검토한 라벨, 나머지 19,600행은 규칙 기반 자동 라벨**입니다.

| 구분 | 행 | 레코드 수 | 만든 방법 |
|---|---|---|---|
| 사람 라벨 | 1~400 | 400 | 검토표 반영 + 직접 라벨링 (2장) |

- 값: 0 / 1 / 빈칸(사람이 판단하지 못한 칸, 15칸). `U`·`NaN` 같은 문자는 쓰지 않음

### 2-4. 근거 문구 규칙

## 3. 자동 라벨 (401~20000행)

### 3-1. 방법

사람이 2만 건을 모두 볼 수 없어서 **규칙 기반 자동 라벨러**(`autolabel.py`)를 만들어 적용했습니다.

1. 항목마다 원문 문장(줄 단위)에서 참가자격·실적·지역·중소기업·확약서·설명회·공동수급·예산 관련 문장을 정규식으로 찾음
2. 메타(적용계약법, 계약방법, 추정가격, 세부품명번호)로 금액 구간·수의·협상·경쟁제품 여부를 판단
3. 2-3의 판정 기준을 코드로 옮겨 0/1을 정함. 근거는 걸린 원문 한 줄(500자 이하)
4. 라벨이 있는 390건(dev 200 + 당시 사람 라벨 190)으로 오류를 보며 규칙을 여러 차례 고침

주요 보정 사항:
- 경쟁제품 판정: 메타 세부품명번호가 비어 있는 경우가 많아 **본문의 10자리 품목번호·품명·사업명**(행사대행, 통학운송, 청소·경비, 정보시스템 유지보수 등)으로도 판정
- "중·소기업"을 "소기업"으로 잘못 읽지 않도록 표기 정규화, 「중소기업기본법」 같은 **법령 이름은 제한 조건에서 제외**
- 여러 줄에 걸친 자격 조항을 이어서 판단, "제2조의3(우선조달 예외)" 명시 시 부재 항목(v16·v18)은 0
- 1원·5원 같은 비정상 추정가격은 "금액 미상"으로 처리

### 3-2. 정확도

| 기준 | Macro F1 | 해석 |
|---|---|---|
| dev 200건 | 0.69 | 이 데이터로 규칙을 맞췄기 때문에 **과대평가** |
| 사람 라벨 190건 | 0.39~0.40 | 실제 성능에 더 가까운 값 |

- 잘 맞는 항목: v2~v8(실적·지역), v14~v16, v18, v22
- 약한 항목: v9(모델 지정), v17, v19, v24
- 정밀도 위주 규칙이라 대부분 항목에서 양성 비율이 사람 라벨보다 낮음(놓치는 쪽)

## 4. 추론 파이프라인에서 쓰는 방식

`dacon_final_pipeline.ipynb`가 `unlabeled.csv`를 두 갈래로 나눠 RAG 사례은행에 넣습니다.

| 갈래 | 사례로 넣는 것 | 이유 |
|---|---|---|
| 자동 라벨(19,600행) | 항목당 양성 최대 40개(규칙 점수 높은 순) + hard negative 4개 → 991개 사례 | 품질이 낮아 수를 제한, 자동 0은 놓친 양성일 수 있어 음성은 적게 |
| 사람 라벨(400행) | 양성 전부 + 항목당 hard negative 8개 → 447개 사례 | 품질이 높아 전부 사용 |
| 사람 라벨 검증셋 | 사람 라벨 레코드 자체를 입력으로 채점(기본 150건) | dev 외의 추가 성능 확인 |

- 빈칸 15칸은 사례·채점 어디에도 쓰지 않음
- dev 공고와 본문이 같은 레코드는 누수 방지로 제외
- 자동 라벨 단계 → 사람 라벨 단계로 사례를 추가할 때 **dev 점수가 오를 때만 채택**
